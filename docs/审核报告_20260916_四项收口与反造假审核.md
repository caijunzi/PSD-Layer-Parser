## 一、① textile_damask allowlist 重建 —— 完成（但如实保留审计失败）

**重建原则**（不做"为了通过而通过"的事）：
- 名单 = 「本 preset 语义类目」∪「介质结构类（外框/折缝）」
- **明确拒绝**屏风系外来**内容**类目（书法题跋/雁群/建筑/人物/林木/远山/水波）——
  它们对壁布语义错误，纳入即等于产出**命名错误的垃圾层**

**复验结果**：
| 项 | 重建前 | 重建后 |
|---|---|---|
| 产出的语义掩模 | **0** | 2（外框 0px + 折缝 88000px 真实产出） |
| 图层数 | 4（退化） | 5 / 6 |
| 屏风系内容类目 | 被拒 | **仍被拒** ✓ |
| 8 维审计 | exit=2 | **仍 exit=2**（-2：④ 4.71%/⑤ 42.4；-3：④ 17.70%） |

**结论（不放宽任何阈值）**：`textile_damask` 的定位是「**可平铺数码纹样**」；
织物实物照/特写应由 `textile_damask_photo` 承担（已 8/8 通过，且推荐启发式已正确路由）。
不合格产物**如实记为失败**，未强行放行。

## 五、过程环境坑（本批新踩，已入记忆）
1. 本机 shell 配置 `HTTP_PROXY/HTTPS_PROXY=127.0.0.1:62042` → urllib 直连本地端口得 **502 假象**；
   须 `build_opener(ProxyHandler({}))` 绕过
2. agent-browser 的 subprocess 调用**输出必须重定向到文件**：`open` 派生的常驻守护进程
   继承管道句柄 → `capture_output=True` 等不到 EOF → **永久挂起**
3. agent-browser 分进程调用会丢页面状态（回落 about:blank）→ 点击流须同会话连续执行
4. Git Bash 精简环境连 `bash`/`sh` 都可能不在 PATH → 编排一律用 Python subprocess
