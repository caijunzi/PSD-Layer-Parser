## 2. 逐项明细

### 2.1 ⑤ 合成等价性：CMYK 比对口径（测量缺陷，非产物缺陷）

**根因**：PLATE 产物是 ICC FOGRA39 真分色 CMYK（含黑版生成，实测 K≈48.5），
而比对参考图用 PIL 朴素 `convert('CMYK')` —— 该实现**K 通道恒为 0**（无黑版、无 TAC/色域映射）。
产物有黑版、参考无黑版 → K 通道系统性错配，把 RMSE 人为推高到 32–42。

**修复**：`_composite_rmse` 改为参考图经**同一 ICC** 分色后比对；返回 `color_managed` 标记，
ICC 缺失时回退朴素转换并**如实标注**（不静默失真）。

**实测（同一 PSB，换口径重算）**：

| 样本 | 旧口径 CMYK | 新口径（同 ICC） | 判定变化 |
| :--- | ---: | ---: | :--- |
| 金地 plate | 36.49 | **0.96** | FAIL → 全过 |
| 商用图 plate | 32.51 | **2.43** | FAIL → 全过 |
| 壁布 plate | 41.86 | 40.31 | 仍 FAIL（真实缺陷） |
| 水墨 design | 2.53 | 2.53 | 通过（RGB 线不受影响） |

修复后金地/商用图 RMSE 与通过的 design 线样本（2.53）同量级，证明此前失败是**测量口径问题**。

### 2.2 指纹标准化 / PCA

**根因**：`fingerprint._pca_model` 恒为 `"placeholder"`，`_apply_pca` 只做截断/填充，
`_scaler` 是恒等（mean=0, scale=1）；`train_pca_from_dataset` **生产零调用**（仅测试导入）。
后果：embedding 是未标准化的原始特征，各特征量纲差 4 个数量级
（`edge_density≈0.1` vs 直方图计数≈1e3），CBR 余弦检索被大尺度特征主导。

**修复**：
- 新增 `tools/train_pca.py`（默认扫描 `inputs/`，支持多目录）。
- `fingerprint.py`：新增 `save_pca_model` / `load_pca_model`，`_apply_pca` 首次调用**自动加载**。
- 模型落盘到 `engine/adaptive/fingerprint_pca.pkl`（2.4 KB，随代码入库）。
  **不放 `checkpoints/`**——该目录被 `.gitignore` 忽略，会导致 clone 后静默失效。
- `n_components` 自适应：上限 `min(期望, 特征数, 样本数-1)`；样本不足时**只标准化不降维**
  （本项目 9 张图 → 主成分仅 8，强行降维反丢信息）。

**实测**：`scaler.mean_=[1.95, 4.288, 72.2, …]`、`scale_=[0.16, 1.485, 17.978, …]`（真实统计），
embedding 84 维有效、长度恒 128（索引硬要求）。

### 2.3 CBR 参数生产化

**根因**：`run_universal_engine.py` import 了 `suggest_auto_tune` 却**从未调用**，
`effective_auto_tune["global_percentiles"]` 被硬编码为 `{}`，`density_bands` 取 preset（通常为空）
→ 归档的 `auto_tune` 恒空 → CBR 命中却无参数可复用（日志 `cbr_applied=false`）。

**修复**：真实调用 `suggest_auto_tune`（大图先降采样到长边 1024 控耗时），产出：
- `global_percentiles`：真实 p50/p75/p90/p95；
- `regions` / `density_bands`：生产生效参数（仅取类目已有 region 与 preset 已配置密度带）；
- `density_bands_suggested` / `regions_suggested`：本次推荐，**单独归档、不自动注入**。

**为何不自动注入**：`density_band_classes` 会被 `grounded_sam_provider` **直接用于产层**，
自动注入会新增图层、改变分层结果，进而**破坏 cold/repeat 字节可复现**（RK-16）。

**实测**：`auto_tune 已计算：p50=0.0592 p90=0.1899 p95=0.2319；推荐密度带 9 条（不自动注入）`；
且新跑产物 SHA 与修复前**完全一致**（`e1c86db4…`），证明只归档、不改产物。

### 2.4 `category_priors` 真实先验

**根因**：表为空 → `inherit_priors()` 只能优雅跳过。

**修复**：新增 `tools/build_category_priors.py`，从真实 episode 检出统计：
- `area_budget_min/max`（框面积 p10/p90）、`elongation_mean/std`、`compactness_mean/std`、
  `n_components_mode`、`n_samples`；
- **按父子关系上卷到祖先**：episode 的 `category_id` 都是三级，若只写三级，二级父类仍无先验、
  继承依旧空转。上卷后二级/根拥有「其所有子类检出」的真实统计。
- 只写库中**已存在**的类目（不臆造 ID）；`--min-samples` 默认 3 防小样本噪声；写入前自动备份 DB。

**实测**：写入 **19 条**；`landscape_painting`(148 框)、`vegetation`(50)、`water`(44)、
`mountains`(28) 等均有真实先验；`waterfalls`/`celestial`/`figures_animals` 现可直接继承。

### 2.5 绢本工笔分层质量（根因：preset 误用）

**根因**：两张绢本样本此前用 `textile_damask`（壁布）preset，其类目为
「巴洛克团花 / 金箔卷草纹样」，而图内容为**花鸟题材**（牡丹、枝叶、禽鸟、山石、水面），
二者完全不匹配 → AI 检测对壁布类目零掩模产出、规则引擎退回屏风系 → 内容大量丢失。

**修复**：改用 `chinese_ink_landscape_ai`（含 `trees_vegetation`/`fauna_geese`/`plum_blossom`/
`mountains_cliffs`/`water_ripples` 等花鸟+山水类目），并更新 `tools/run_all_samples_e2e.py` 的 CASES。

**实测**：

| 样本 | 旧 preset | 旧 ④ / ⑤ | 新 preset | 新 ④ / ⑤ | 判定 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| 绢本-1 | textile_damask | 8.712% / 26.72 | chinese_ink | **0.004% / 1.86** | FAIL → **8 维全过** |
| 绢本-2 | textile_damask | 20.004% / 44.63 | chinese_ink | **0.292% / 2.17** | FAIL → **8 维全过** |

④ 改善约 2000× / 68×，⑤ 改善约 14× / 21×。**结论：这是 preset 选择错误，不是算法能力不足。**

> 注：`材质判别` 仍把绢本判为「绢本工笔」（织物+暖色，与壁布同族），当前以显式指定 preset 覆盖。

## 3. 残余未闭环项

**壁布 plate（`damask_sample.png`）⑤ 合成等价性仍失败（40.31）。**

已定位的根因链：
1. `textile_damask.ai_semantic_classes` 仅 **2 个类目**（巴洛克团花 / 金箔卷草纹样），覆盖不足；
2. 该 preset 的 `rule_class_allowlist = ["02_巴洛克团花_Baroque_Medallion"]`，而 provider 规则引擎
   产出的全是**屏风系**类目（`09_Calligraphy`/`06_Architecture`/`05_Trees`/`03_Distant_Mountains`/
   `11A_Brocade_Outer_Frame` 等）→ 被 allowlist **全部丢弃**；
3. 同时 AI 检测对这 2 个壁布类目**零掩模产出**（DINO 有 box、无有效层）；
4. 最终产物仅剩 `01_Ivory_Fabric_Base` + `11_Unclassified_Ink_Residue` + 2 个工艺层（共 4 层）
   → 大马士革花纹内容丢失 → 合成图偏亮（墨量仅 ICC 参考的约一半）、RMSE 高。

修复需按品类**重建 `textile_damask` 的类目定义与掩模链路**（属独立专项，涉及多次出图验证）。
本次**未通过放宽审计阈值**掩盖该缺陷——`④ 内容承载` 之所以未同时报错，是因三个残/工艺层
bbox 均为全画布、掩码并集覆盖全图形成假通过，这一点已记录待查。

### 6.4 ★ audit_psb 量测缺陷（影响面大于 ④ 假通过本身）

排查 §3 记录的「④ 假通过」时，发现更深的缺陷。`psd_tools` 的 `layer.numpy()`
**通道数随色彩模式变化**：

| 模式 | shape | Alpha 位置 |
| :--- | :--- | :--- |
| RGB（design 线） | (H, W, 4) = R,G,B,**Alpha** | index **3** |
| CMYK（PLATE 线） | (H, W, 5) = C,M,Y,K,**Alpha** | index **4** |

而 `_alpha` 写死 `a[:, :, 3]` → **在 CMYK 产物上取到 K 通道**（ICC 分色后呈色恒 1.0）
→ 掩码全判「全画布」→ ②分辨率真实性 / ③实例重复 / ④内容承载 / ⑥底板纯净度 **四维全错**。

**实测量化**（`scratch/quantify_alpha_bug.py`）：

| case | 模式 | union 修复前 → 后 | lost_ratio 修复前 → 后 |
| :--- | :--- | :--- | :--- |
| 01 damask | cmyk | **100.0% → 38.1%** | 0.0（假通过）→ **0.112863** |
| 02 金地原图 | cmyk | **100.0% → 63.77%** | 0.0 → 0.003829 |
| 03 金地商用 | cmyk | **100.0% → 69.95%** | 0.0 → 0.001469 |
| 04~09 design | rgb | **完全相同** | **完全相同** |

→ CMYK 产物 union 修复前**恒为 100%**；**RGB（design 线）完全不受影响**
（4 通道下 index 3 本就是 Alpha）——这正是此前「只有 PLATE 线样本问题多」的原因。

**一并修复**：
- 新增 `_layer_rgb`：④/⑥ 此前把 CMYK 的 **C,M,Y 当成 R,G,B** 与源图比对。
  psd_tools 对 CMYK 返回**呈色**（=1−墨量），实测象牙底板 C=.961 M=.910 Y=.829 K=1.000
  （墨量 K0%）→ `R=v0*v3, G=v1*v3, B=v2*v3`。
  ⚠️ 该转换为**无 ICC 近似**，仅用于「底板 vs 源图」阈值 40 的粗判；⑤ 仍走同一 ICC，不受影响。
- ④ 的 union 排除**加工层**（新增 `TH["process_names"]`）：`12_激光冲孔挂点` Alpha 覆盖 **100%**、
  `13B_复古金专色` 89.8%，纳入即把 union 撑满。修复后 `carrier_layers=1, excluded_process_layers=2`。
- ⑦ 的 `a[:, :, 3]` 是**有意**取 K 通道（真黑版判定），已收紧为 `shape[2] >= 5` 并加注释。
