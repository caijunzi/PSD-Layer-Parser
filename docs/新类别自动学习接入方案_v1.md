# 新类别自动学习接入方案 v1（设计稿 · 2026-09-17）

> 目标：当用户提供一张**不属于现有训练类别**的新品目样图时，系统能平滑、优雅地
> 将其纳入自动学习流程并高可用落地。本方案基于已落地的底座（matched/reason 结构化
> 推荐、`unknown_samples.jsonl` 待标注队列、8 维审计门禁、金标准回归守卫），
> 遵循两条铁律：**人始终是确认关卡**；**运行期不改生产配置与模型**（保 RK-16 字节可复现）。

---

## 一、现状底座（已落地，本方案直接复用）

| 已有能力 | 位置 |
|---|---|
| 推荐可信度结构化（matched/reason/family_conf） | `webui/backend/core/file_handler._recommend_preset` |

## 二、端到端流程（六阶段）

```
用户上传新图
   │
[A] 运行期自动识别与标记
   │   分类器 vN 输出 top1 置信 + top1-top2 margin
   │   ├─ 命中现有族 → 正常推荐
   │   └─ 拒识（top1<T_R 或 margin<T_M）→ 打 suspect_new_family 标记
   │        → unknown_samples.jsonl 追加（含 128D embedding）
   ▼
[B] 样本入库与人工审核（WebUI「未知样本审核页」）
   │   列表 + 缩略图 + 聚类自动归组预览
   │   人工三选：①归入现有族 ②创建新族（≥3 张相似样本才允许）③丢弃
   │   创建新族 → taxonomy.json 版本+1（decision_log 留痕）→ 样本移入 inputs_training/<新族>/
   ▼
[C] 增量训练触发（自动提示，不自动执行）
   │   满足任一：a) 某族达标(≥15)且较上次训练增量≥5
   │            b) 新族样本 ≥5
   │            c) 距上次训练 ≥14 天且有新样本
   ▼
[D] 训练与评测（tools/train_material_classifier.py --train）
   │   留出 20% 评测：holdout 准确率 ≥95% 且混淆矩阵逐族合格
   │   且同集严格优于规则判别器 v1 —— 不达标出差距报告，不发布
   ▼
[E] 模型更新与发布
   │   训练产物版本化 material_clf_vN.pkl（含训练集哈希/评测报告）
   │   写入 staging → 金标准回归守卫（5 金标准 + 12 样本全量审计，结果不劣才转 stable）
   │   原子切换 stable 指针 → manifest 记录分类器版本
   ▼
[F] 灰度 / 回滚 / 容错
       canary 灰度（仅披露两版差异，不改推荐）→ 人工核对 N 个任务 → 转 stable
       回滚 = 指针回退（秒级），运行中任务不受影响
       模型加载失败 → fail-open 回退规则判别器 v1（已验证路径）+ P0 日志
```

## 三、各阶段详细设计

### 阶段 A：运行期自动识别与标记

- **判定点**：T1 分类器（`material_clf_vN.pkl`）输出后，在 `_recommend_preset` 的
  材质命中分支追加**双重拒识判据**：
  - `top1_conf < T_R`（建议 **0.55**，与现有未匹配封顶值对齐）；
  - `top1_conf - top2_conf < T_M`（建议 **0.10**，双族摇摆=识别不可靠）。
- **落点**：满足任一 → `matched=False, reason="reject_low_margin"`，
  追加记录时**附带 128D embedding**（当前队列无 embedding，需扩展写入）。
- **向后兼容**：阈值经 `ULS_REJECT_TR` / `ULS_REJECT_TM` 环境变量可调，默认即上述值。

### 阶段 B：样本入库与人工审核

- **新增 API**（挂在 adaptive.py）：
  - `GET /api/adaptive/unknown-samples`（已有，扩展返回 embedding 摘要）；
  - `POST /api/adaptive/unknown-samples/review`：`{action: "assign"|"new_family"|"drop", ...}`。
- **前端**：WebUI 新增「未知样本审核」页——列表（缩略图/时间/判别结果）+
  **聚类归组预览**（对 embedding 做 KMeans，K=候选簇数，每簇给代表图）。
- **新族创建门槛**：某簇 ≥3 张相似样本才允许「创建新族」（防单图成族）；
  创建 = taxonomy.json `families[]` 增项 + `version` 递增 + decision_log 记录
  （谁/何时/基于哪几张样本）→ 样本从队列移入 `inputs_training/<新族>/`。
- **审计与留痕**：审核动作本身追加到 `taxonomy_decision_log.jsonl`（可追溯）。

### 阶段 C：增量训练触发

- 实现为 `tools/train_material_classifier.py --check-trigger`：
  读队列与语料计数，输出「建议训练/不建议 + 原因」，由人或定时任务调用。
- **不做自动发布**：触发只产出"可训练"提示与预填参数，训练与发布必须过阶段 D/E。

### 阶段 D：训练与评测

- 分类数**动态**：直接读 taxonomy.json 的 families（新增族自动进入训练）。
- **门禁（全部满足才允许 --save）**：
  1. 每族样本 ≥ `target_per_family`（15）；
  2. holdout 准确率 ≥ 0.95 且每族召回 ≥ 0.90；
  3. 同集对比严格优于规则判别器 v1；
  4. 金标准 12 张 + 5 金标准审计结果与旧版一致或不劣（防"拆东墙补西墙"）。

### 阶段 E：模型更新与发布

- 版本化：`material_clf_v1.pkl, v2.pkl, …`；`material_clf_stable.json`
  记录 `{stable: "vN", canary: "vN+1"| null, updated_at, train_hash, holdout_acc}`。
- **manifest 记录**：每次运行的 manifest 写入 `material_classifier.version`，
  可追溯每个产物用的是哪个模型。
- **发布 = 原子改写 stable 指针文件**（写临时文件 + os.replace）；无需重启后端。

### 阶段 F：灰度 / 回滚 / 容错（高可用核心）

| 机制 | 设计 |
|---|---|
| 任务内版本绑定 | 任务开始时加载并固定分类器实例到该任务上下文——**运行中任务不受发布影响**，天然不中断 |
| 灰度 canary | 新版先以 canary 运行 N 个任务：两版结果**并排披露**在 manifest（不改变实际推荐），人工核对一致或更优后转 stable |
| 回滚 | `stable` 指针回退一级；**秒级生效**（下一个任务即用旧版），无半更新状态 |
| 容错 | pkl 加载失败/特征维度不匹配 → **fail-open** 自动回退规则判别器 v1（已验证路径），并记 P0 级日志——与现有"任何检测失败安全降级"原则一致 |
| 可复现 | 同一任务内分类器版本固定 → RK-16 语义保持；版本号入 manifest 可追溯 |

## 四、接口与文件契约汇总

| 文件/接口 | 角色 |
|---|---|
| `engine/adaptive/material_taxonomy.json` | 家族体系 SSOT（版本化 + decision_log） |
| `webui/data/unknown_samples.jsonl` | 未匹配/疑似新族队列（扩展 embedding 字段） |
| `GET/POST /api/adaptive/unknown-samples[/review]` | 队列查询与人工审核动作 |
| `engine/adaptive/material_clf_vN.pkl` | 版本化模型（含 feature_names/classes/report） |
| `engine/adaptive/material_clf_stable.json` | stable/canary 指针（发布=改指针） |
| `tools/train_material_classifier.py` | 校验/训练/评测/触发检查（--check-trigger） |
| manifest.totals.material_classifier.version | 产物→模型的可追溯绑定 |

## 五、分期落地

| 里程碑 | 内容 | 依赖 |
|---|---|---|
| **M1** | T1 分类器训练完成并达标（依赖语料：每族 ≥15） | 用户投喂样本 |
| **M2** | 拒识双阈值 + unknown 队列带 embedding + 审核页（assign/new_family/drop） | M1 |
| **M3** | 增量触发器 + 版本化发布（stable/canary/回滚）+ 金标准守卫接入 | M2 |

当前已具备：阶段 A 的队列与提示卡（短期 1+2 已上线）、阶段 D/E 的工具骨架。
M2 的审核页与 M3 的发布指针是主要新增开发量（预估各 1 个批次）。

## 六、风险与对策

| 风险 | 对策 |
|---|---|
| 新族样本过少即训练 → 过拟合 | 新族创建门槛 ≥3 张 + 训练门禁每族 ≥15 + 不达标不发布 |
| 审核误操作污染体系 | taxonomy 版本化 + decision_log 可追溯 + git 管理可回滚 |
| 模型上线后质量回退 | 金标准回归守卫 + canary 披露 + 指针秒级回滚 |
| 生成图分布偏差 | 来源 CSV 记录 + 生成:实拍混合比要求（7:3 起步） |
| 运行中任务被发布影响 | 任务内版本绑定（任务开始加载、生命周期内不变） |
