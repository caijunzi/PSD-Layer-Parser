## rename/delete/merge 真实实现 + Stage 5 e2e（2026-09-14 00:45，commit 906256b）

### 三个操作从 TODO 转真实实现
- **rename**：更新 `categories.name_zh / name_en / name_template`
  - name_template 保留原序号前缀（如 `NN_`）后按 `{name_zh}_{name_en}` 重建
- **delete**：**软删除**（置 `deleted_at`）
  - 选软删而非硬删的关键理由：categories 被 category_prompts / category_material_affinity /
    category_priors 外键 **CASCADE** 引用，硬删会连带清空学到的权重且不可恢复；
    历史 episode JSONL 也记录 category_id，硬删会让回放松散引用
  - 软删后由 `db_manager` 主查询 `c.deleted_at IS NULL` 过滤 → 等价于不可见
- **merge**：源 prompts 迁移到目标（同名 prompt 取权重较大者，绕 `UNIQUE(category_id, prompt)`）
  + 源类目软删；拒绝「缺 target / 目标不存在 / 目标==源」
- 统一返回 `{ok, action, detail}`；失败不再静默，API 明确 400
